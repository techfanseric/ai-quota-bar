# v1.36.0 release record

- Version 1.36.0, macOS build 72. Minor bump: the account row now shows whichever of the local and cloud values was sampled more recently, and provenance moved from invented words to an icon plus a tooltip. No behaviour that a patch could carry, and no packaging change.
- Commits: `450b962` (sample-time merge + per-account cycle switcher + source icons), `1852912` (scope label, member-name truncation, deficit reference line), `6863570` (the vocabulary refactor that removed `Latest` / `Mix`), plus `1372943` (release notes, version bump, homepage strings, changelog feed).
- **The Makefile build number was stale again and would have caused a downgrade.** `APP_BUILD ?= 68` was v1.35.0's number while this Mac was already on build 71 — a plain `make install` would have written 68 over 71. Bumped to 72. **Read the installed build before running `make install` from this repo.**
- Validation: full Swift suite **645 tests, 4 skipped, 0 failures**, run unloaded. `swift build -c release` clean. Cloudflare `npm run check` clean; `npm test` **124 tests, 123 pass / 1 fail** — the pre-existing `tests/team.test.js:107` "dashboard session", not touched here.
- **One test is load-sensitive and fails whenever the machine is busy: `MobileDashboardSecurityTests.testLoopbackWakeVideoSupportsSafariByteRangesAndSecurityHeaders`.** It starts a loopback HTTP server and waits on `await fulfillment(of: [ready], timeout: 5)` — a hardcoded 5-second wall-clock timeout. Under CPU contention (two suites in parallel, or a release build running) the listener is not ready in time and the test reports 2 failures / 1 unexpected. Reproduced 3 of 3 times under load, 0 of 3 unloaded, with a 24s vs 13.6s runtime difference. **Not a regression from this release** — none of the three commits touch MobileDashboard, and the test exists unchanged in `origin/main`. Not fixed here: the fix is a timeout/`URLSession` robustness change to a file this release does not otherwise touch. **It is the one thing worth fixing next.**

- **The network was unstable throughout this release and it cost three separate failures that were all retried, not worked around.** A `git push` died with `RPC failed; curl 52 Empty reply from server` and succeeded on retry. A `gh release create` with all three assets died with `HTTP 408: Upload body timed out` and **rolled the whole release back** — the release had to be created without assets and each asset uploaded separately. A Pages deploy died with `UND_ERR_CONNECT_TIMEOUT` to `api.cloudflare.com:443` after 48 of 52 files and succeeded on retry. The cause is the local proxy (`HTTP(S)_PROXY=http://127.0.0.1:7897`); direct and proxied connections both work, they just drop intermittently.
- **A retry loop that reports success when the upload failed.** The first asset-upload loop was written as `if gh release upload … | tail -2; then echo OK; fi` — a pipeline's exit status is the **last** command's, so `tail` returned 0 and the loop printed `OK AIQuotaBar.pkg` for an upload that had actually returned 408. The DMG and `SHA256SUMS.txt` were genuinely up; the pkg was not. Caught only because the final asset listing was checked against the real sizes. **Capture the command's status before piping it, or do not pipe it at all.**
- Website: `npm run sync:releases` synced 56 published releases; `name_en`/`body_en` for v1.36.0 added by hand as with every prior release, with the key order matched to v1.35.0 (`tag_name, name, published_at, html_url, body, name_en, body_en`). Homepage version strings updated to v1.36.0 in both zh and en. Deployed; `/`, `/en/`, `/changelog`, `/en/changelog` all 200, both changelogs render v1.36.0 with the correct language title and **no cross-language leakage** (the zh page contains no English title and vice versa). `/v1/app-update` reports 1.36.0 pointing at the pkg.
- The Cloudflare token is the **fourth** column of the `node.cyberic@gmail.com` row, and the cell wraps it in backticks. Stripping them is required: passing the raw cell produced a 55-character credential, which fails with `Authentication failed (status: 400) [code: 9106]` — a code that reads like a permissions problem and is actually a formatting one. **The secrets file is still to be read by account name, never by row position** (it is the last of six rows), and the token must never be printed.
- **Two stale strings v1.35.0 left on the homepage were fixed here** rather than carried forward: the download button still read "下载公开版 DMG" / "Download DMG" while it had linked to the installer package since that release, and the install FAQ still taught the mount-and-drag flow and the DMG ad-hoc signing story. Both now describe the package.
- **The render snapshot still shows the word "Mix", and that is a stale test fixture rather than a shipping path.** `LeftMenuCodexAccountRenderTests` hardcodes `detail: "Pro 20x · Mix · resets 10/01 20:36"` and does not set `mergedSourceKinds`. The row's source label is only printed when the source kinds are a subset of `.local`, and `AccountSourceKind.kind(forSource: "Mix")` maps to `.local`, so the fixture lands on exactly the branch that prints the word the refactor removed. The real merge path (`UsageViewModel.markMixed`) writes the detail source and the merged kinds together, so a merged row always has a remote kind and always draws an icon instead. **The latent hole is real though**: any future path that sets `source = "Mix"` without the kinds will put that word back on screen. Also dead: `MenuView.nonCurrentAccountTrailingSummary` is defined and never called, and it would print `Mix` too.
- Known boundaries: the merge needs a sample time on both sides and stays local-first when either is missing; the horizontal reference line decides on the pace stage rather than the delta sign, because the two delta conventions in this codebase have opposite signs; a merged row renders only the winner but remembers both sides in `mergedSourceKinds`, which is what the tooltip reports.
