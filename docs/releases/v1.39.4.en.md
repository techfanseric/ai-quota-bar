# v1.39.4 — Lightweight mode, Magpie multi-account rings and cycle notifications

macOS 1.39.4 (build 87). Windows remains its separate v1.38.6-beta.1
prerelease and does not include this change.

## One-minute lightweight mode

Settings → General → System → Lightweight mode is on by default. The
left-click and right-click panels, Settings and the warning window release
their recreatable interface resources one minute after being dismissed;
reopening within that minute cancels the release. Hidden panels are not
loaded in the first place.

The menu-bar rings keep their quota, trends, model lights, hover details and
alerts. Background quota refresh, task protection, Dim, sync, reporting and
the LAN dashboard are not paused. Visible, minimized or sheet-carrying
windows are never released.

Saved settings, accounts and history are kept, and the settings tab and
window position are restored on rebuild (subject to the display layout).
Unsaved temporary input may be cleared. The actual memory benefit depends on
the open page and system caching, so no fixed number is promised.

## Quota refresh with provider apps closed

Codex now refreshes through the saved-sign-in OAuth-first pipeline even when
Codex and ChatGPT are closed. When a local Magpie gateway is configured, its
multi-account quota report is preferred; when Magpie is missing or unhealthy,
the original active-account reader is used automatically. AIQuotaBar never
touches Magpie's credentials.

The default Codex ring follows the current account, and the Codex Pool
aggregate stays available as the explicit alternative. **Each account with a
request actively being processed upstream now gets its own C ring** (up to
three), replacing the single Codex ring while those accounts are active. Each
account ring shows that account's quota and an active dot, and hovering
identifies it using the existing account-masking preference. The left-click
menu expands every in-use account by default, including aliased accounts,
while respecting manual collapse. Idle activity returns to the existing single
ring; ambiguous or temporarily unavailable account activity is explained
rather than presented as idle.

In Settings → General → Menu bar, choose Always visible and Select all to
show every configured, enabled quota ring even when the matching provider app
is closed. Always-visible rings override Follow running apps; left-click
sections still collapse automatically. AIQuotaBar itself must keep running.

## Model-based activity lights

The lights now follow the model family rather than the Codex client. With a
local Magpie configured, the actual routed request drives the matching
Codex/Kimi/GLM/MiniMax ring: a Codex client calling MiniMax through the
local Magpie route lights the MiniMax ring, and a GLM call lights the GLM
ring. Hovering shows the model names and the request counts.

Counts follow the actual route including fallbacks, not the client's name.
Direct local model tasks keep their lifecycle signal, and the same work is
not counted twice as a task and as a request. Unknown aliases are not
guessed. A gap while a local tool runs may show no gateway lights, while task
power protection continues.

## Quota cycle-end notifications

When a registered 5-hour, weekly or monthly window ends, AIQuotaBar refreshes
first and then sends one deduplicated summary covering whether the old cycle
was exhausted and what the new cycle has left. It notifies whether or not the
old cycle was exhausted. Account names reuse the menu masking setting.
Notifications still depend on macOS permission and Focus, and can be turned
off in Settings → Usage & Team → Refresh.

## Task lifecycle reconciliation

Codex hooks and rollout logs are now reconciled by turn: a terminal signal
wins over a lagging copy, finished or canceled work is cleared, and child
sessions that can be attributed are merged into one task so the same work is
not counted twice. Hook activity keeps being counted while sleep protection
is off.

This also fixes a real defect: the turn-end grace timer could fire early and
then never re-arm itself, so power protection could hold forever. The timer
is now armed for the remaining time with zero tolerance, which makes an early
fire harmless.

## Privacy boundaries

Provider login credentials are never uploaded. The Magpie report is read
from its local public interface without touching its credentials. Lightweight
mode only changes when local interface resources are released. The Dim bridge
accepts dim requests only, does not expose restore, and stores no key or
pointer data.

Install the PKG to replace the app in Applications. Requires macOS 14+ on
Apple Silicon. The app is ad-hoc signed; the installer is unsigned and not
Apple-notarized.
