# v1.37.0 — 关注的数据不再被丢掉，气泡也终于收得走

macOS build 73。这一版修的是同一类毛病：**一个值该显示哪一个，不该由「谁先占了那个位置」决定。** 上一版让本机和云端按「取较新」合了起来，这次把关注通道拉进同一套规则；顺带修掉了悬停提示在菜单里撤不掉的老毛病。

## 关注的那一行，不再因为位置被占而消失

你把一个邮箱加进「关注的账号」，是因为想看它。而同一时刻它很可能还有另一份数据：这台 Mac 本身就登录着它（`~/.codex/accounts/<邮箱>.json`），或者团队里另一台设备正在上报它。于是同一个窗口上会同时存在云端行和关注行。

原来的去重按 key 走，key 被占住的那一方直接丢掉——丢的恰好是关注那一路。实测一个真实账号：关注通道 7 秒前刚拉回来的数据被扔掉，换上一行可能两天前的云端值，眼睛图标也跟着消失，于是这行读起来变成「这是云端数据，不是你关注的」。

现在两份合成一行：**采样更晚的那次胜出**，和本机 vs 云端是同一条规则。两侧的来源都留着，所以既被关注、又在云端有数据的账号会同时画出云朵和眼睛，而不是二选一。

胜出那一行自己的来源标记不改写。`"Cloud"` 还管着跨天快照的日期显示和云端的可见周期上限，合成两行不该顺手把这些规则关掉。

## 悬停提示：自己接管，不借系统的

账号头、供应商标题、cycle 芯片原本都用 `.help()` 说明自己。在 NSMenu 里这件事从来没真正成立过：菜单的模态事件跟踪会吃掉菜单项内部的鼠标移入与移出，挂在里面的跟踪区域收不到「离开」，AppKit 于是认为指针还停在那儿，提示窗口就赖在屏幕上不撤——指针早就移开了，气泡还在。

所以悬停这条链路现在自己做。每个锚点把 id 和自己在菜单坐标系里的位置一起上报，菜单根层统一画气泡。只报 id 会把气泡钉在行里（会被 ScrollView 裁掉），只报位置就得再串一条回调链把悬停事件层层捅回根层。

- **350 毫秒后才出现。** 账号行和 cycle 芯片是紧挨着的列表，鼠标横扫过去没有延迟就是一串空泡闪个不停
- **下方放不下就翻到上面**，宁可换边也不要半个气泡被面板窗口裁掉——残缺的样子看起来同样像「卡住没消失」
- **气泡本体不接鼠标事件**，否则它会把自己脚下的悬停抢走，变成「鼠标还停在那儿，气泡却不见了」
- **菜单关闭时清掉悬停状态**，否则下次点开菜单会凭空冒出一个气泡

## 「多久之前」会换挡

一个两天前停止上报的关注账号，读作「888 分钟前更新」。这个数字算得对，但没法用：是 15 小时还是 3 天？两种情况该做的动作不一样，而读者得先在心里做一次除法。

现在按尺度换挡：一分钟内说「刚刚」；一小时内说分钟；一天内说小时；超过一天直接给日期和时刻。到了那个量级，「多久」已经不重要，「是哪一刻」才重要。

最后一档用显式格式串并把语言钉死，不跟系统语言跑——否则中文界面上会冒出 `10/5/26, 2:32 PM` 这种半中半英的串，长度还随地区变化。这里显示的是界面的语言，不是系统的语言。

## 已知边界

- 合成要求两边都有采样时间；缺一边时保留原来那一行。「没法比」不等于「关注那一路更新」
- 气泡宽度上限 248pt，长正文会换行；高度按行数估算，只用来决定翻不翻面，不追求精确
- 悬停延迟固定 350ms，不跟随系统的辅助功能设置
- 关注通道与团队云端是两条独立通道，账号同时在两边时仍然只画一行——但两枚图标都在
