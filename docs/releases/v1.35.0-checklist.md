# v1.35.0 release record

- Version 1.35.0, macOS build 68. Minor bump on two counts: the menu bar placeholder is a new three-way setting, and the release artifact changed from a disk image to an installer package. The placeholder **default changed** (brand mark → OpenAI connectivity), which is a behaviour change no patch can carry.
- Commits: `07d7bac` (menu bar features + the watch timestamp fix), `f31f2bd` (pkg build), `ebc39f7` (release notes + version bump + homepage strings), plus the changelog feed sync.
- **The build number in the Makefile was stale and would have caused a downgrade.** `APP_BUILD ?= 64` while v1.34.0 shipped build 64 and the local machine was already on build 67 (65–67 were unreleased dev builds). A plain `make install` would have written 64 over 67. Bumped to 68 and used for the release. **Read the installed build before running `make install` from this repo.**
- **The runtime shims intercept `rm`/`mv` on this machine.** `make install` moves the installed app aside to a temp dir before copying the new one in, and `make pkg`/`make dmg` `rm -rf` staging dirs. Run these with a clean PATH (`env -i HOME="$HOME" PATH=/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin`) or the recoverable-delete shim silently no-ops and the step half-applies. `pkgutil --expand` also refuses an existing target directory, so temp paths must not be pre-created by `mktemp -d`.
- **The in-flight work was not mine and was reviewed before shipping.** A PKG-installer change set (Makefile `pkg` target, `scripts/pkg/{Distribution.xml,scripts/preinstall,scripts/postinstall}`, `UpdateChecker` asset preference, `worker.js` asset selection, README/SPEC, `.gitignore`) was sitting uncommitted from 16:09–16:22. The user chose to ship it, and asked for a completeness read first. Findings below.
- **Both installer scripts are validated on a real machine, not just in tests — they have no automated tests at all.** The package built during this session was installed twice on this Mac (20:35:39 and 20:37:06). `/var/log/install.log`:
  - `preinstall: closing AIQuotaBar (pid: 2071)` — quit by pid
  - `postinstall: installed AIQuotaBar to /`, then `relaunching AIQuotaBar for ericyim`
  - `postinstall: scheduling installer removal for /tmp/AIQuotaBar.pkg /Users/ericyim/Downloads/AIQuotaBar.pkg`
  - cleanup job's own logger output: `removed /tmp/AIQuotaBar.pkg` and `removed /Users/ericyim/Downloads/AIQuotaBar.pkg`, then `launchd: removing service: com.techfanseric.aiquotabar.installer-cleanup`
  - after both runs: the launchd job is unloaded and `/Library/LaunchDaemons/…cleanup.plist`, `/private/var/tmp/aiquotabar-installer-cleanup.sh` and the relaunch flag are all gone. Zero residue.
  - **Remaining gap:** no shell-level test for either script. Real-machine evidence does not survive refactors the way a test does. This is the first thing to add.
- `pkgbuild` prints `write: Permission denied` four times per build. Reproduced: it is pkgbuild failing to propagate `com.apple.provenance` extended attributes off the app bundle, and it is **benign** — the package is written, and the app extracted from the payload passes `codesign --verify --deep --strict` ("valid on disk", "satisfies its Designated Requirement") with 60 files and `CFBundleShortVersionString 1.35.0` / `CFBundleVersion 68`. Not fixed; it is noise, and stripping the xattr would be a cosmetic change to someone else's in-flight work.
- **The package is unsigned and not notarized** (the app inside is ad-hoc runtime signed; `pkgutil --check-signature` → "no signature"). The install log records `The package "AIQuotaBar.pkg" is not signed` as a **non-fatal** trust-evaluation failure, and both installs completed. But both were from `/tmp` and a local `~/Downloads` copy. A user double-clicking a browser download will hit a heavier Gatekeeper prompt than the DMG did. Stated plainly in the release notes with the workaround. **This is the support cost of the pkg, not a defect.**
- The DMG is still built and still attached, because the service and the in-app updater both fall back to it and the repo keeps `make dmg` for that reason. `/v1/app-update` now reports `AIQuotaBar.pkg` as `download_url`, which is the intended preference.
- The watch timestamp fix was verified in production before release, not only in tests: the other Mac is still on the old build and published `sampledAt = 2026-10-11T15:59:37Z` (the weekly window's reset, five days out). After the server deploy its next publish at `2026-10-06T05:00:30.564Z` was clamped to the publish time, with `resetsAt` left intact. **An owner who never updates produces correct rows for everyone else** — that is what the read-side and server clamps are for.
