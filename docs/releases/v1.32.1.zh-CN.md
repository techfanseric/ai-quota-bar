# v1.32.1 — 跨设备关注 Codex 账号、菜单栏环逐服务商取数

macOS build 62。

## 关注另一台 Mac 的 Codex 账号

- 一台 Mac 登录的 Codex 账号，现在可以在另一台 Mac 的菜单栏里直接看到——不必、也不需要在第二台机器上登录它。
- owner 那台机器自己抓额度，再把结果按白名单吐给局域网内被授权的对端。**Codex 登录凭据始终不离开 owner 那台机器**，也不经过任何服务器；线上只有额度百分比和重置时刻。
- 入口在「设置 → 服务商 → Codex → 关注账号」，一个区块两半：
  - 「允许其他 Mac 关注我的账号」：全局开关 + 逐账号勾选，**默认全关**，未列出的邮箱一律不外发。
  - 「我关注的账号」：添加 / 移除对端，填局域网地址、端口与访问密钥。
- 访问密钥复用「手机看板」那一把，不用额外分发第二套凭据；**分享额度不要求打开手机看板**，只开关注开关时局域网服务照常起来，但看板与账号名掩码策略不受影响。
- 添加对端会先握手再入库：地址写错、对方没开分享、密钥不对，当场给出一句明确的话，而不是加进去之后菜单里永远挂一个连不上的条目。
- 访问密钥有三重限制：只发往回环 / 私有网 / 链路本地地址（粘公网地址进来本地就拒）、**拒绝一切重定向**（否则一个 302 就能把令牌骗去别的主机）、令牌只进 Authorization 头不进 URL。密钥存在钥匙串，删除对端时真删。
- 授权可随时收紧并立即生效；对方撤销后，关注侧会清掉本地缓存，不会继续显示一份已经不获授权的额度。
- 对端不可达、额度窗口已过这两种「没有新数据」会分开显示，不会混成一个看不懂的错误。

### 被关注的账号不会自己消失

云端账号数据超过时效阈值后会被整条隐藏——对云端团队数据这是对的，但对你明确点名要看的账号是错的：账号会因为对方机器安静下来而从菜单里凭空消失。关注来的账号走另一条路：窗口过期时把显示区间撑到当下，行还在并标 `stale`；对端断线时保留上一份数据，而不是让数字清零。

另外，从别的 Mac 关注来的账号**不会被这台机器再分享出去**：本机只是「看」了它，没有资格替它做二次传播。

## 菜单栏环：逐服务商选取数窗口

- 菜单栏圆环的外环与中心此前共用一个全局窗口选择，想让 Codex 读 Weekly 就没法同时让 Kimi 读它自己的当前窗口。
- 现在可以逐服务商设置外环与中心的取数窗口；未单独设置的跟随全局默认。
- 该服务商不支持所选窗口时（例如 MiniMax 没有周窗口）自动回落到当前窗口，不会画出无意义的数据。
- General 页新增每个服务商各自的窗口选择器，改动即时反映到菜单栏。

## 管理后台：额度明细可追溯

- 后台此前只显示每个账号的最新快照，无法看出这个数字怎么变成现在这样——**一个错误的数字和一次真实飙升看起来一模一样**。
- 新增单账号的原始采样历史查询，带显式行数预算；返回被截断时明确告知，避免把一份残缺数据当成完整数据渲染。
- 预算优先保留最新数据：取最旧的一段会让繁忙账号静默显示几天前的数字，却没有任何提示。
- 支持按模型过滤，宽账号不会把预算浪费在马上会被过滤掉的兄弟模型上。
- 不认识的查询参数直接拒绝而不是忽略——一个拼错的参数会返回 200 加默认区间，看起来像「筛选生效了」。
- 后台明细页改为按模型列展示，历史数据按需加载。

## 其它

- 本机用量清理逻辑改名：`pruneDelivered` 只删云端已确认的行，但这个 helper 也会删掉已无消费方的本机行，旧名字让第二个调用点看起来像误用。
