# v1.28.0 — AI task protection covers all four providers

macOS build 56.

## AI task protection now includes GLM and MiniMax

- "AI task protection" used to keep the Mac awake only during Codex and Kimi tasks; **GLM and MiniMax coding tasks on this Mac now participate too**. Task counts, the protection popover, and the mobile dashboard task list merge all four providers.
- Three new read-only, passive local detectors (no message content is ever read):
  - **GLM (ZCode)**: reads the session database shared by the ZCode desktop app and CLI; an interactive session counts as working while it keeps updating.
  - **MiniMax CLI**: reads each session's `manifest.json` update time under `~/.minimax/v2/sessions`.
  - **Claude Code bridge**: GLM / MiniMax tasks run through Claude Code with a custom endpoint are attributed to the matching provider by the responding model name in the transcript (other models, such as the official Anthropic endpoint, never trigger protection).
- Detection uses one signal — a session updated within the last ~2 minutes — plus the existing 5-minute turn-end grace period. All assertions are still released the moment tasks finish or the app exits.
- Which providers participate still depends on local presence: GLM needs a Keychain plan credential or a ZCode installation; MiniMax needs a plan token or a MiniMax CLI session store.
- The menu status line lists the locally detectable providers dynamically (for example, "Ready · waiting for Codex, GLM, Kimi, and MiniMax"); the system power assertion name is now the neutral "an AI task is working".

Note: MiniMax CLI detection is based on session manifest freshness, and its task-count edge cases are still being calibrated.

Requires macOS 14+; the DMG targets Apple Silicon and keeps the ad-hoc signature without Apple notarization.
