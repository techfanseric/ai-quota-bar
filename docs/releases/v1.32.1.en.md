# v1.32.1 — Watch a Codex account from another Mac, per-provider ring windows

macOS build 62.

## Watch another Mac's Codex account

- A Codex account signed in on one Mac can now be observed from another Mac's menu bar — without signing it in there, and without needing to.
- The owner machine does the fetching and serves the result to an approved peer on the LAN. **Codex credentials never leave the owner machine**, and nothing transits a server; only remaining percentages and reset times are sent.
- Both halves live in Settings → Providers → Codex → 关注账号:
  - "Let other Macs watch my accounts": a master switch plus a per-account checkbox, **off by default**. An email that is not listed is never sent.
  - "Accounts I watch": add or remove a peer by LAN address, port and access key.
- The access key is the one from Mobile Dashboard, so no second credential has to be handed out. **Sharing quota does not require enabling the mobile dashboard**: with only the sharing switch on, the LAN service still runs, but the dashboard and its account-name masking policy are unaffected.
- Adding a peer handshakes first, so a wrong address, an unshared owner or a bad key fails immediately with a specific message instead of leaving a permanently unreachable row in the menu.
- The access key has three constraints: it is only ever sent to loopback / private / link-local addresses (pasting a public address is rejected locally), **every redirect is refused** (otherwise a single 302 could walk the token to another host), and the token only ever travels in the Authorization header, never in a URL. It is kept in the Keychain and genuinely deleted with the peer.
- Authorization can be tightened at any time and takes effect immediately; when the owner revokes access, the watching side drops its local cache instead of continuing to show quota it is no longer allowed to see.
- "No new data" for two genuinely different situations — peer unreachable, and quota window elapsed — is reported separately rather than collapsed into one confusing error.

### A watched account never disappears on its own

Cloud account data is hidden once it passes a staleness limit. That is right for cloud team data, and wrong for an account you deliberately asked to watch: the account would vanish from the menu whenever the other machine went quiet. Watched accounts take a different path — when the window elapses the display range is stretched to cover now, the row stays and is marked `stale`; when the peer goes away the last known values are kept rather than dropping to zero.

Separately, an account learned from another Mac is **not re-shared by this machine**: it only watched that account, and has no business publishing it onward.

## Menu bar ring: per-provider data window

- The outer arc and the reserve centre previously shared one global window choice, so you could not read Codex as Weekly and Kimi as its own current window at the same time.
- Both windows are now configurable per provider; anything left unset follows the global default.
- When a provider cannot source the requested window (MiniMax has no weekly window) it falls back to the current window instead of rendering something meaningless.
- General gains a window picker per provider, and changes reach the menu bar immediately.

## Admin console: quota detail is now traceable

- The console showed only the latest snapshot per account, with no way to see how that number got there — **a wrong figure and a genuine spike looked identical**.
- Raw sample history is now served for a single account behind an explicit row budget, and truncation is reported so a capped response can never render as a complete one.
- Newest rows win the budget: taking the oldest slice made a busy account silently display days-old numbers with nothing to say so.
- A `model` filter keeps a wide account from spending its whole budget on siblings the console filters away anyway.
- Unrecognised query parameters are rejected rather than ignored — a typo used to answer 200 with the default range, which reads as a working filter.
- The detail view renders history as model columns and loads history lazily.

## Also

- The local-usage pruning helper is renamed: `pruneDelivered` only dropped cloud-acknowledged rows, but the helper also removes local rows nothing can consume, so the old name made the second caller look like a misuse.
