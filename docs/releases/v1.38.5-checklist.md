# v1.38.5 release record

- macOS feature release 1.38.5, build 81. Credential guard mirror: every Codex account seen
  on this Mac keeps a copy of its credentials outside `~/.codex`, and an external tool that
  rewrites the sign-in is named in the panel instead of silently changing the current account.
- Mirror path `~/Library/Application Support/com.techfanseric.aiquotabar/codex-auth-mirror/<digest>.json`,
  directory 0700, files 0600, atomic writes, directory created on first write only. It follows
  `~/.codex/auth.json` and every file in `~/.codex/accounts/`; it never participates in switching.
- Watching: both the `~/.codex` directory and the `auth.json` file itself, plus a 10-second
  background fallback poll. Measured on this machine: an in-place write produces **no** directory
  event, while an atomic replace kills the file-level watch (its fd points at the removed inode).
  Watching only one side therefore misses real cases; both are watched and the file watch is
  re-armed on every directory event.
- Panel: a "Signed in outside this app" row with an orange warning triangle and the
  switched-away/switched-to accounts. Verified by rendering the accounts section to PNG
  (`CodexAccountSwitchPopoverRenderTests`, state `accounts-external-change`).
- Also fixed a guard that never worked: `URL.resourceValues(forKeys:)` caches resource values on
  the same URL instance. Writing one file three times in a row returned the same modificationDate
  every time, so the tear-read protection compared a cached value with itself and always passed.
  Now uses a fresh stat (`FileStamp`).
- Release validation is being rerun after adding incremental activity and rendering optimizations; see the final publication entry below.
- Installed and restarted /Applications/AIQuotaBar.app at 1.38.5 (81). Live verification on the
  real `~/.codex` passed: mirror directory and permissions correct, all four credentials mirrored
  byte-for-byte, in-place and atomic rewrites both detected, external switch detected, probe
  removed, and every credential verified byte-identical to the pre-test baseline afterwards.
- The real `~/.codex` was never modified: `auth.json` and all three pool files still carry their
  original account ids, refresh tokens and `last_refresh` timestamps, with original mtimes.
- Release build completed successfully. Retains existing ad-hoc application signing and unsigned
  PKG distribution.

- Includes event-driven Kimi/MiniMax history checks, Codex metadata reuse, unchanged-render guards and event-driven display discovery. Refresh and animation cadence remain unchanged.
- Performance limitations and active-task CPU/memory measurements are recorded in `docs/performance-audit-2026-10-23.md`; idle CPU below 1% is not claimed. Experimental GPU animation is not included.
- Reinstalled and restarted the current release build; installed main executable SHA-256 `03b583e6dd1066735267dcaeeadc9eee976bd298bcb3b2ffee54fd366084f382`.
