# v1.33.0 release record

- User rejected the v1.32.1 interaction outright ("我不要输入什么密钥，就开通允许其他mac关注我的账号，然后直接输邮箱账号就好了") and then corrected the transport ("不是局限于局域网，是通过云端来同步的啊", "跟手机看板没有半毛钱关系"). The v1.32.1 LAN design was torn out and replaced rather than extended.
- Version 1.33.0, macOS build 63 — a **minor** bump, not a patch: the feature's transport changed and a public HTTP endpoint was removed, so this is not a backward-compatible fix.
- Commits: `b5de2b1` (watch a Codex account by email over the team cloud), `c136698` (release notes + version bump + homepage version strings), `e52c036` (changelog feed sync).
- **No backend change.** The reuse of the existing team cloud channel was the whole point: `/v1/quota-samples` already stores per-account quota and already serves it back to other team members. The watcher side needed only an email address; the backend is untouched and no new public endpoint or app-wide shared key was introduced. Team isolation (`docs/team-isolation.md`) is unrelaxed.
- Root cause of the rework: v1.32.1 invented a new peer-to-peer channel instead of noticing the team cloud channel already in the app, which is exactly what produced the IP + port + access key form.
- Removed: the `/api/v1/watch/quota` endpoint, the "keep listening so an account can be watched" branch in `MobileDashboardService.shouldRunListener` (the dashboard is back to listening only when enabled), and `CodexWatchPeerClient` / `PeerStore` / `ResponseBox` / `PeerModel` / `Projector` / `Payload` / `GrantStore`. The installed binary contains 180 `CodexWatchStore` symbols and **0** `CodexWatchPeerStore`/`CodexWatchProjector` symbols.
- Legacy `codexWatch.isServing` / `codexWatch.grants.v1` are read and migrated on init, so accounts ticked under v1.32.1 carry over. Covered by a regression test.
- Validation: full Swift suite **567 XCTest tests, 4 pre-existing skips, 0 failures**. `swift build -c release` clean. Cloudflare `npm run check` clean; `npm test` 100 pass / 1 fail.
- Pre-existing unrelated failure: `cloudflare/tests/team.test.js:107` "dashboard session: login, overview, revoke". Verified by stashing this release's cloudflare changes and re-running on a clean tree — fails identically. This release touched only `public/index.html` and `public/en/index.html` under cloudflare, no source.
- Two defects found by self-review before shipping, both fixed with tests:
  - The email validator's allowed-character set omitted `@` itself, so every legitimate address was rejected by the final `allSatisfy` and the feature was a silent no-op.
  - The Add button's disabled condition was exactly the set of conditions that produce an inline error, so none of those error messages were reachable. It is now disabled only when the field is empty.
- Design decisions worth keeping:
  - **Switch off = no filtering at all.** Existing team users see zero behavior change on upgrade; only someone who turns the switch on gets per-account control. The switch governs Codex only.
  - **Share list is sourced from the accounts actually signed in on this Mac**, not from `providerUsageSections`, which is already merged with team cloud data and contains teammates' accounts. Sourcing from the merged view would let this Mac re-publish a colleague's quota as its own.
  - Three "no data" states are reported separately (`noTeam` / `waitingForPublisher` / `available`) because the user action for each is opposite; one generic message sends people looking for something to reinstall.
  - A watch-only machine now loads cloud data at startup; previously that path was gated on the share toggle, so a read-only watcher showed empty rows until the next refresh.
