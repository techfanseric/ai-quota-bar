# v1.33.0 — Watching a Codex account now takes one email, over the cloud

macOS build 63.

## Watching a Codex account: one email address

The previous release (v1.32.1) built this feature as a **LAN peer-to-peer link**: the Mac holding the sign-in started its own plain-HTTP server, and the watching Mac had to type an IP address, a port and an access key. That made it heavy to use, it only worked on the same Wi-Fi, and it sent you to Mobile Dashboard to find the key.

This release replaces it. The transport now uses the **team cloud channel the app already had**; the backend is unchanged and authorization still uses the existing device credentials.

**The watching side now takes a single email address** — no address, no port, no access key, and no Codex sign-in on the watching Mac.

- Turn on "Let other Macs watch my accounts" and tick the accounts to share; their quota syncs to your team's cloud alongside Share account quota.
- On the watching Mac, enter that email under "Accounts I watch" and press Add. The account appears in the menu as its own group row, with a status line reading "Team cloud · N entries · updated …".
- **Codex credentials still never leave the machine they are signed in on**; only remaining percentages, reset times and the plan name travel.

### The complete flow now

1. Put both Macs in the **same team** under Settings → Team — create one, or join with the invite code. This is one-off; the member passphrase is kept in this Mac's Keychain and is not asked again.
2. On the Mac signed in to the Codex account: turn on "Let other Macs watch my accounts", tick the account, and make sure **Share account quota** in the Team section is on.
3. On the Mac that wants to watch it: enter the email under "Accounts I watch" and press Add.

The team is the authorization boundary of this channel, not a usability compromise: the cloud isolates data per team, so without joining one there is nothing to read.

### The sharing side shares nothing by default

With the switch on, only individually **ticked** Codex accounts are uploaded; unticked ones are not sent at all. Quota with no account name is not uploaded either — it cannot be watched by email, so keeping it would only suggest that something is being shared.

**With the switch off, no filtering happens at all**: every Codex quota upload behaves exactly as "Share account quota" did before, so existing team users see no behavior change on upgrade. The switch also only governs Codex and does not affect the existing Kimi / GLM / MiniMax sharing behavior.

### No relaying someone else's account

The share list is taken from the **account store of accounts signed in on this Mac**, not from the merged view the menu renders. The latter already includes what teammates reported, so sourcing it from there would make this Mac re-publish a colleague's quota as its own. This Mac only looks at that account; it has no standing to share it.

### Three different "no data" states, reported separately

- **Not in a team** → "Not in a team yet, so no one else's account can be read."
- **Channel fine, but no snapshot for this email in the cloud** → "No data yet. Ask them to tick this address on their Mac, and check that Mac is running."
- **Data available** → "Team cloud · N entries · updated …"

These need opposite actions from the user, so collapsing them into one "no data" message would send people looking for something to reinstall.

### Also fixed

- A Mac that only wants to **watch** other accounts, without sharing its own quota, now loads cloud data properly. Previously the startup path was tied to the Share account quota switch, so a watch-only machine showed empty rows until the next refresh.
- The Add button is now disabled only when the field is empty. Invalid or already-watched input stays clickable and explains itself — a button that does not say why it is greyed out is worse than clicking and being told the format is wrong.

## What was removed

v1.32.1's LAN channel is gone in full:

- The `/api/v1/watch/quota` HTTP endpoint, and the "keep listening just so an account can be watched" branch the mobile dashboard service grew for it — the dashboard is back to only listening when you enable it.
- `CodexWatchPeerClient` / `CodexWatchPeerStore` / `CodexWatchResponseBox` / `CodexWatchPeerModel` / `CodexWatchProjector` / `CodexWatchPayload` / `CodexWatchGrantStore`.
- The per-peer tokens kept in the Keychain under `codexWatch.peer.<uuid>` (adding a watched account no longer produces any).

That channel's hand-rolled access key, address allowlist, redirect refusal and header-only token constraints went with it — there is no longer a credential to distribute across processes. Nothing in the team isolation guarantees (`docs/team-isolation.md`) was relaxed, and no new public endpoint or app-wide shared key was introduced.

Upgrading from v1.32.1: previously ticked accounts are migrated automatically (read from `codexWatch.isServing` / `codexWatch.grants.v1`) and do not need re-ticking.

## Also

- Mobile Dashboard is back to "listens only when you enable it": in v1.32.1, enabling account sharing alone also brought the LAN service up.
