# v1.23.0 — 降低常驻负载，看清存储与上传状态

macOS build 49。

## 持续监测，减少重复计算

- 修复菜单栏外观回调反复生成整套动画帧的问题。仅在可见内容、主题、尺寸或显示缩放变化时重建，保留原有 30 fps 动画与监测频率。
- 本机用量改为增量处理变化会话及其关联分支，持久化轻量索引；界面只加载最近 35 天，无变化时复用统计结果。磁盘上的旧记录不删除。
- 一台 10 核、16 GiB Mac 的现场测量中，进程平均 CPU 从旧版约 95.39%（61 秒）降至约 9.07%（新版 10 分钟）；100% 表示一个核心。新版物理内存采样约 121–177 MiB，旧版重启后约 346 MiB。结果取决于机器、日志规模与活跃任务，不是所有设备的保证。

## 存储与上传可核查

- 用量设置显示本地数据库及日志占用、原始 Codex 日志大小、额度重试队列大小，以及已确认、待上传、拒绝和仅本地记录数。
- 显示最近上传回执、最早待传记录与重试时间；提供只读云端核验，按当前成员、设备和固定时间范围比较记录数及各项 token 总量。
- 修复额度快照包含不被服务端使用的完整利用率历史，导致请求过大、HTTP 413 和重试积压的问题。新请求和旧队列重试均按团队接口精简；失败继续保留待重试文件，旧绑定数据保持隔离。
- 未绑定上传目标的历史不等于已备份，不会自动补传。现有额度队列容量上限不变，长期断网仍可能淘汰最旧快照；本机 token 事件使用独立持久化队列。

## 数据保留边界

本次只减少内存加载，不启用自动删除或有损历史汇总。最近明细、较早按日、更远按月的分级保留仍是后续方案；未确认上传记录应保留原始事件。Codex 管理的原始日志不由本软件清理。
