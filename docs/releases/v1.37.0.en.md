# v1.37.0 — the watched row stops disappearing, and the tooltip can finally leave

macOS build 73. This release fixes one recurring mistake: **which value a row shows should not be decided by which side claimed the slot first.** The last release made local and cloud merge by "take the newer"; this one pulls the watched channel into the same rule — and fixes the long-standing problem of a tooltip that cannot leave the menu.

## The watched row no longer disappears because its slot is taken

You add an address to the watch list because you want to see it. At the same moment it probably has another source too: this Mac is signed in as it (`~/.codex/accounts/<address>.json`), or another device in your team is reporting it. So the same window carries a Cloud row and a Watch row at once.

Rows were de-duplicated by key, and whichever side found the key occupied was dropped — which was the watched one. On a real account, this cost exactly what it sounds like: the watch fetch had succeeded seven seconds earlier, and that number was thrown away in favour of a Cloud row that could be days old. The eye icon went with it, so the row read as "cloud data, not something you watched" — the opposite of what adding the address was for.

The two now merge into one row: **the later sample wins**, the same rule local-versus-cloud already used. Both sides' sources are kept, so an account that is both watched and cloud-reported draws the cloud *and* the eye rather than picking one.

The winner's own source segment is left alone. `"Cloud"` still decides the stale-snapshot date display and the cloud cycle visibility limits, and merging two rows must not quietly switch those off.

## The tooltip: ours, not the system's

The account header, the provider header and the cycle chips all explained themselves through `.help()`. Inside NSMenu that never actually worked: the menu's modal event-tracking loop swallows mouse-moved and mouse-exited for views inside an item, so the tracking area never learns the pointer left, AppKit keeps believing it is still there, and the tooltip window stays on screen long after the cursor is gone.

The hover chain is ours now. Each anchor reports its id together with its frame in one named coordinate space, and a layer at the root of the menu draws the bubble. Reporting only the id would pin the bubble inside the row, where the ScrollView clips it; reporting only the frame would mean threading a callback up through every section.

- **350ms before a bubble appears.** Account rows and cycle chips sit next to each other, and with no delay a sweep of the pointer is a string of empty bubbles flashing past.
- **It flips above the row when there is no room below**, rather than being clipped in half by the panel window — a half bubble reads as "stuck and will not go away" too.
- **The bubble takes no hit-testing**, or it would steal the hover from the anchor under it and close itself while the pointer rests there.
- **Hover state is cleared when the menu closes**, otherwise a bubble pops into existence the next time you open it.

## "How long ago" changes gear

A watched account that stopped reporting two days ago read as "Updated 888m ago". The number is arithmetically correct and practically useless: is that 15 hours or three days? Those two call for different actions, and the reader has to do the division in their head first.

The tiers now follow the scale: just now under a minute, minutes under an hour, hours under a day, and past a day the day and the time it was measured. At that point "how long" stops mattering and "which moment" takes over.

The last tier uses an explicit format string with a pinned locale rather than following the system language — otherwise a Chinese interface would print "10/5/26, 2:32 PM", with a width that moves around per region. This string is the interface's language, not the system's.

## Known boundaries

- The merge needs a sample time on both sides; when either is missing the row that was already there stays. "Cannot compare" is not "the watched one is newer"
- The bubble is capped at 248pt wide and wraps; its height is estimated from the line count purely to decide whether to flip, and is not measured
- The 350ms hover delay is fixed and does not follow the system's accessibility setting
- Watch and team cloud remain two independent channels. An account in both still renders as one row — with both icons on it
