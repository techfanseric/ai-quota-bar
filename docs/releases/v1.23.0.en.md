# v1.23.0 — Lower background load, visible storage and delivery status

macOS build 49.

## Keep monitoring with less repeated work

- Fix appearance callbacks repeatedly rebuilding every menu-bar animation frame. Rebuild only when visible content, appearance, size or display scale changes; retain 30 fps playback and existing monitoring intervals.
- Process changed local-usage sessions and their related branches incrementally, persist lightweight indexes, and reuse unchanged statistics. Load only the latest 35 days into the interface while retaining older records on disk.
- On one 10-core, 16 GiB Mac, average process CPU fell from 95.39% over 61 seconds to 9.07% over a ten-minute run. Here 100% means one CPU core. Sampled physical memory was approximately 121–177 MiB versus 346 MiB after restarting the old version. Results depend on hardware, log volume and active tasks; these are not universal guarantees.

## Inspect storage and delivery

- Usage settings show database and journal bytes, original Codex log size, quota retry-queue bytes, and acknowledged, pending, rejected and local-only record counts.
- Show the latest upload acknowledgement, oldest pending record and retry time. A read-only cloud check compares record counts and all token totals for the current member, device and a fixed time range.
- Fix oversized quota snapshots causing HTTP 413 and retry backlogs. New uploads and queued retries omit full utilization histories that the team endpoint does not consume. Failed retries retain their files, and legacy bindings remain isolated.
- Unbound history is not a cloud backup and is not automatically uploaded. The existing quota queue limit remains; prolonged outages can still evict its oldest snapshots. Local token events use a separate durable outbox.

## Retention boundaries

This release reduces in-memory history without deleting or lossily aggregating stored events. Recent detail, older daily summaries and distant monthly summaries remain a future retention proposal. Unacknowledged events should retain their original records. Original logs managed by Codex are not cleaned by this app.
