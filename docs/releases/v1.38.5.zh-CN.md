# v1.38.5 — 凭据守护与后台性能优化

macOS 功能版，build 81。

- 本机见过的**每一个** Codex 账号，都会在 `~/.codex` 之外留一份凭据副本：
  `~/Library/Application Support/com.techfanseric.aiquotabar/codex-auth-mirror/<账号指纹>.json`，
  目录 0700、文件 0600、原子写。目录在首次写入时才创建。
- 镜像跟随 `~/.codex/auth.json` **和**账号池里的每个备份，只跟随、绝不参与切换——
  切换仍然只在 auth.json 与账号池之间做原子改名，镜像永远不会被读走或移动。
- app 常驻监听 `~/.codex` 目录与 `auth.json` 文件本身，任一被改写就同步；
  另有一条 10 秒的后台兜底轮询。外部工具（magpie 这类网关）换走登录态的那一刻，
  那个账号的凭据已经留在镜像里了。
- 登录态被外部工具改写时，账号分区会直接显示「登录态被外部改写」以及被换走、
  换上的账号；本应用自己发起的切换不会算成外部改动。
- 顺带修掉一个一直空转的隐患：`URL.resourceValues(forKeys:)` 在**同一个 URL 实例**上
  会缓存资源值，实测连续三次写同一个文件、三次读到的 modificationDate 完全一样。
  原来的撕裂读防护（读前读后比对 mtime 与大小）建在这上面，前后比的是同一个缓存值，
  比对恒为真，**防护从来没有生效过**。现改用新鲜 stat，防护与版本号才真正成立。
- 既有的账号切换、面板渲染与云同步行为不变；watch 账号与团队云同步走独立通道，不受影响。

详见[凭据守护镜像](docs/codex-auth-guard.md)。

## 减少后台重复工作

- Kimi、MiniMax 改为文件事件与增量历史检查，保留漏事件恢复及周期核对。
- Codex 复用未变化的脱敏任务元数据；菜单栏跳过无变化状态和关闭菜单的布局；显示器发现改为配置事件驱动。
- 保持配额刷新、任务检测周期及动画播放节奏。
- 单机活动任务测试中，五分钟平均 CPU 为 12.12%，此前一分钟基线为 21.76%。这不是空闲基准或性能保证：后续不同负载窗口测得 17.65%。尚未证明空闲低于 1%，原生菜单栏动画重绘仍是热点。
- GPU 动画实验未随版本发布，其菜单栏副本播放和外观等价性尚未验证。

内存、方法及限制见[性能复核](docs/performance-audit-2026-10-23.md)。
