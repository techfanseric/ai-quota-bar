# v1.33.0 — 关注账号改走云端，只填邮箱

macOS build 63。

## 关注账号：只填一个邮箱

上一版（v1.32.1）把这个功能做成了**局域网点对点**：登录了账号的那台 Mac 自己起一个明文 HTTP 服务，想看的那台 Mac 要手填 IP、端口和一份访问密钥。结果是操作步骤重、只能在同一个 Wi-Fi 下用，还得先去「手机看板」里翻密钥。

这一版整个换掉。传输改走 app 早就有的**团队云端通道**，后端一行代码没改，鉴权沿用现有的设备凭据。

**现在关注方要填的只有一个邮箱**：不需要地址、不需要端口、不需要访问密钥，也不需要在关注方登录 Codex。

- 打开「允许其他 Mac 关注我的账号」，勾选要分享的账号，它就跟着「共享账号额度」一起同步到团队云端。
- 关注方在「我关注的账号」里填那个邮箱、点添加，菜单里就出现该账号的分组行，状态行显示「团队云端 · N 条 · 更新于 …」。
- **Codex 登录凭据仍然永远不离开登录它的那台机器**，线上只有额度百分比、重置时刻和套餐名。

### 现在的完整步骤

1. 两台 Mac 都在「设置 → 团队」里，创建或用邀请码加入**同一个团队**（一次性，成员口令存本机钥匙串，之后不用再填）。
2. 登录了那个 Codex 账号的 Mac：打开「允许其他 Mac 关注我的账号」，勾选该账号，并确认「团队」区块的**共享账号额度**是开着的。
3. 想看的那台 Mac：在「我关注的账号」里填邮箱，点添加。

团队是这条通道的鉴权边界，不是可用性上的将就：云端按团队隔离数据，没有加入团队就什么都读不到。

### 分享侧默认一个都不共享

打开开关后，只有**逐个勾选**的 Codex 账号会被上报；没勾的一个都不传。账号名为空的未归属额度同样不上报——它没法被按邮箱关注，留着只会让人以为在共享。

**开关关着的时候完全不做任何过滤**：所有 Codex 额度照旧按「共享账号额度」的原有行为上报。已经开了团队同步的老用户升级后行为一个字都不变。这个开关也只管 Codex，不影响 Kimi / GLM / MiniMax 原有的共享行为。

### 不转发别人的账号

分享名单取自**本机登录着的账号仓库**，不是从菜单用的那份合并数据里取的。后者已经和团队云端合并过了，里面混着别人上报的账号——从那里取会让本机把同事的额度当自己的再转发一次。本机只是「看」了它，没有资格替它分享。

### 三种「看不到数据」分开显示

- **没加入团队** → 「还没加入团队，暂时读不到别人的账号」
- **通道正常但云端没有这个邮箱的快照** → 「还没数据。让对方勾选这个邮箱，并确认那台 Mac 在运行」
- **有数据** → 「团队云端 · N 条 · 更新于 …」

这三种对应的用户动作完全相反，混成一句「无数据」会让人以为该重装点什么。

### 顺带修正

- 只想**看**别人账号、不想共享自己额度的机器，现在也会正常拉取云端数据。之前启动时和「共享账号额度」开关绑死，导致纯关注的机器启动后关注行要空到下一次刷新才有内容。
- 「添加」按钮只在输入为空时禁用。输入不合法或已关注过时保持可点并给出具体原因——一个不解释自己为什么灰着的按钮，比点一下看到一句「格式不对」更让人卡住。

## 移除的内容

v1.32.1 的局域网通道整条删掉：

- HTTP 端点 `/api/v1/watch/quota`，以及手机看板服务为此多起来的「被关注也要监听」的分支——手机看板回到「只有自己打开才监听」的原有语义。
- `CodexWatchPeerClient` / `CodexWatchPeerStore` / `CodexWatchResponseBox` / `CodexWatchPeerModel` / `CodexWatchProjector` / `CodexWatchPayload` / `CodexWatchGrantStore`。
- 钥匙串里按 `codexWatch.peer.<uuid>` 存放的对端令牌（新增关注时不再产生）。

原来那套的自建访问密钥、地址白名单、拒绝重定向、令牌只进 Authorization 头等约束随通道一起消失——因为不再有需要跨进程分发的凭据。团队隔离（`docs/team-isolation.md`）的既有约束一条都没有放松，也没有新增任何公开端点或 app 级共享密钥。

从 v1.32.1 升级的用户，之前勾选过的账号会自动迁移过来（读取 `codexWatch.isServing` / `codexWatch.grants.v1`），不用重新勾。

## 其它

- 手机看板回到「只有自己打开才监听」：v1.32.1 里为了分享额度，会在只开关注开关时也把局域网服务拉起来。
