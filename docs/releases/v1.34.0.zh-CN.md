# v1.34.0 — 关注账号：只填邮箱，不要团队也不要密钥

macOS build 64。

## 关注账号：现在只要知道邮箱

前两版都把「知道账号就能看」这件事做复杂了。v1.32.1 做成局域网点对点，要手填 IP、端口和一份自建密钥；v1.33.0 改走团队云同步，传输对了，但仍要求两台 Mac 先用邀请码加入同一个团队。

这一版把中间那一层也去掉：**只要知道邮箱，任何装了 AI Quota Bar 的 Mac 都能读到那个账号的额度。**

- 不需要建团队、不需要邀请码、不需要访问密钥、不需要 IP 和端口
- **两台 Mac 不需要在同一个网络** —— 传输走 app 自带的云端服务
- 关注方**不需要**在自己机器上登录 Codex
- 分享方只需要：打开「允许其他 Mac 关注我的账号」→ 勾选那个邮箱

入口还是「设置 → 服务商 → Codex → 关注账号」。

### 数据流

```
登录了账号的那台 Mac                         关注方那台 Mac
┌────────────────────────────┐             ┌──────────────────────────────┐
│ 本机 Codex 凭据 → 抓额度    │             │ 「我关注的账号」填一个邮箱    │
│            ↓               │             │            ↓                 │
│ 只发布勾选的账号             │  POST       │ GET /v1/watch/quota?email=…  │
│  百分比 / 重置时刻 / 套餐名  │ ──────────► │  邮箱本身就是查找键           │
│            ↓               │             │            ↓                 │
│ /v1/watch/publish          │             │ 菜单里按账号分组显示            │
│  整体替换：空数组=全部取消   │             └──────────────────────────────┘
└────────────────────────────┘
```

Codex 登录凭据**永远不离开登录它的那台机器**。线上只有额度百分比、重置时刻和套餐名。

## 这条链路的边界，说在前面

**读路径对「知道这个邮箱的人」是开放的。** 这是「不要团队、不要密钥」的直接后果，不是疏漏：不要求团队、不要求密钥，就意味着服务端没有可以核对的秘密。真正的授权是 owner 在设置里**逐个勾选**那个邮箱 —— 勾了就是「知道这个地址的 Mac 可以看我的额度」，取消勾选**立刻**从云端删除。

服务端存的是 `sha256(归一后的邮箱)`，表里没有明文邮箱。但要说清楚：**哈希只保证服务端不存明文地址，不构成访问控制** —— 任何人都能算出一个地址的查找键。

在这个前提下仍然守住的：

1. **默认拒绝。** 打开开关后只有逐个勾选的 Codex 账号会被发布；没勾的一个都不发。账号名为空的未归属额度同样不发 —— 它没法被按邮箱关注。
2. **只发百分比。** 对外只有额度百分比、重置时刻和套餐名。没有 token、没有 API key、**没有绝对用量**（绝对量会暴露这个人真实烧了多少）。
3. **撤销立即生效。** 发布是**整体替换**语义，所以取消勾选会立刻从云端删除该行，不需要等下一轮刷新，也不需要单独的撤销接口。
4. **过期数据不冒充现值。** 超过 3 小时没更新的快照会标成「数字可能是旧的」，而不是把旧数字当现值渲染。行仍然保留 —— 你点名要看的账号不该凭空消失。
5. **被读取是可查的。** 分享侧能看到每个账号被读取过几次、最后一次是什么时候。只含计数与时间，**不含读取者身份**；owner 的手段是「取消勾选」，不是拉黑某个读取者。
6. **不转发别人的账号。** 分享名单来自本机登录着的账号，不是从菜单那份已经和团队云端合并过的数据里取的 —— 后者混着别人上报的账号，从那里取会让本机把同事的额度当自己的转发出去。
7. **不碰团队体系。** `/v1/watch/*` 是独立命名空间，读不到团队数据、设备凭据或后台。团队隔离的既有约束一条都没有放松。
8. **有速率限制。** 读取按来源 IP 限流（120 次/小时），发布按发布方限流（120 次/小时）。
9. **一个地址只能被一个发布方占用。** 第二个发布方会被拒绝（409），否则原发布方后续的「取消分享」会删不掉这一行，账号会永久留在云端。

端点鉴权用的是 app 自带的内置 key（服务端叫 `SYNC_TOKEN`），每个安装都自带、零配置。**它不是秘密** —— 就写在二进制里。它的作用是挡住随手 `curl` 的探查、给读取一个归属桶、让限流有依据；真正的授权是上面第 1 条的勾选。

## 打开开关就会自己去抓数据

分享侧要发布的内容来自本机这一轮抓到的额度。刚打开开关时通常一帧数据都还没有，所以开关打开时会先跑一次用量刷新，拿到数据再发布 —— 不需要你手动点刷新。

同时把误导性的空态文案改了：列表为空时**不再**说「这台 Mac 还没有登录任何 Codex 账号」（可能是根本没抓到，不是没登录，两者用户动作完全相反），改成「还没有拿到这台 Mac 的 Codex 额度数据」并给一个重试按钮。

## 修掉的三个问题

- **抓取失败会误删云端快照。** Codex 抓取失败那一轮本机没有数据，原本会发布一个空集，而发布是整体替换语义 —— 一次网络抖动就等于把这个账号取消分享。现在没有本机数据时根本不发。
- **过期数字被当成现值。** 状态判定里先检查了「有没有快照」再检查「过不过期」，而缓存快照在过期时是故意保留的（行不该消失），于是 2.5 小时前的数字会以「云端 · N 条」的形式显示为现值。现在过期判定优先。
- **可分享账号列表是陈旧的。** 它原本是 `@State`，只在打开面板和账号增删时刷新 —— 用量刷新后不会更新。改成计算属性，永远跟着最新一次抓取走。

## 与前两版的差别

**v1.32.1（build 62）**：局域网点对点。owner 端自己起明文 HTTP 服务，对端手填 IP、端口、自建密钥。只能同一 Wi-Fi 用。已删除：局域网端点、七个 `CodexWatch*` 类型、手机看板为此多起来的「被关注也要监听」分支。

**v1.33.0（build 63）**：改走团队云同步通道。该版本对团队通道做的上报过滤与启动读取改动，在本版本**全部撤回** —— 团队同步行为回到与关注功能无关的原有状态。

从 v1.32.1 升级的用户，之前勾过的账号会自动迁移（读 `codexWatch.isServing` / `codexWatch.grants.v1`），不用重新勾。
