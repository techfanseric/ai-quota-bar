# Released in v1.39.4 · Background quota and always-visible rings (macOS)

Codex quota now refreshes with Codex/ChatGPT closed. When Codex is configured for a local Magpie gateway, AI Quota Bar first reads Magpie's multi-account quota report. The default Codex ring follows the current account, with an optional Codex Pool aggregating every saved subscription; hover shows each account's most limiting window, percentage and reset time. Magpie retains refresh-token ownership; AIQuotaBar reads only the local report and no Magpie credential. If Magpie is missing, unconfigured, stopped or returns no usable Codex card, the same refresh falls back to the existing saved-sign-in OAuth-first pipeline. Reset-boundary refresh also remains active. Configured Kimi, GLM and MiniMax sources continue to refresh independently of their desktop applications.

In Settings → General → Menu bar, choose **Always visible** and **Select all** to keep every configured, enabled provider ring visible. This setting overrides **Follow running apps** for quota rings; left-click sections can still collapse automatically. Pausing a provider or deselecting its ring still hides it. Work-aware mode remains available.

AI Quota Bar itself must keep running. Saved credentials must be valid, or supported refresh/sign-in is required; an error is not reported as a successful quota reading. The existing native CLI refresh/fallback may run when needed. The pool percentage averages each account's most limiting readable window because Magpie commonly reports percentages without a comparable absolute capacity across plans; failed accounts stay visible and count conservatively as unavailable. These source changes are not included in the public macOS v1.39.3 download and do not add Windows ring controls.

See the [Magpie source comparison](../research/magpie-quota-2026-11-12.md) for the exact provider differences.

## Codex in-use account rings

A Magpie `busy` lane means that account has a request **currently being processed by the provider upstream**. AI Quota Bar merges it with the current trace seat's account identity: when several accounts have upstream requests, the Codex column shows a C ring per account instead of adding a separate pool overview. Each ring shows that account's own quota (preferring 5h) and an active dot; at most three rings are shown, with remaining in-use accounts named in hover. Ordering is stable by busy count and account name.

With multiple Codex rings, hover identifies each masked account, its quota and "In use now"; a single ring keeps the existing whole-strip summary. The left-click menu expands every in-use account by default, including aliased accounts, while explicit manual collapse still wins. Idle or genuinely ambiguous activity returns to the existing single Codex ring, with ambiguity explained; a temporary read failure retains the last known account and quota and marks activity unavailable. The two-second concurrency snapshot can miss very short requests and does not claim to reproduce Magpie's scheduling decision. macOS only; no Windows feature, remote gateway access, Magpie credential read or activity upload was added. See [scheduling research and final behavior](../research/magpie-ring-scheduling-2026-11-17.md).

## Task activity accuracy

Codex hooks and rollout logs now reconcile session/turn identities. Explicit logged completion/cancellation can end a turn whose Stop hook was lost; a stopped hook turn is not relit by a lagging log. Late tool events cannot reopen a completed turn, and an older terminal signal cannot end newer work. Known child sessions count under their root; children still running after their root stops keep the task visible. An empty read does not imply completion.

Turning sleep protection off stops power protection while hook activity counting continues. Each polling batch for ZCode, MiniMax and Claude Code is merged once, reducing transient count changes between sources.

Lights also follow each model family on the existing four rings, rather than treating all Codex-client work as a Codex model. When Codex is configured for a local Magpie gateway, existing concurrency/trace metadata identifies actual in-flight models, including fallback; hover lists model names and counts. Direct local models use turn metadata; unknown group aliases are not guessed. The same work is not added as both a task and a gateway request. Tool gaps may have no gateway lights while full-task power protection continues independently. Discovery accepts configured loopback URLs only, reads no Magpie credentials and uploads no metadata. Other clients retain their freshness-based limitations. Windows is not changed. See [semantics, design and validation](../task-activity-reconciliation.md). Released in [v1.39.4](v1.39.4.en.md).
## Quota cycle-reset notifications

Every registered local quota window can now announce its own reset. After the existing reset-boundary refresh succeeds, AI Quota Bar sends one deduplicated macOS notification per account/model window, whether or not the old cycle was exhausted. The body summarizes the old cycle’s usage and the refreshed allowance; if a provider still reports zero, the notification says the server-side reset may be delayed. Notifications respect macOS authorization and Focus settings, reuse menu account masking, and can be disabled in Settings → Usage & Team → Refresh. The synthesized Magpie Codex Pool ring is excluded so one account reset does not produce duplicate pool/account alerts. AI Quota Bar must be running; an event is delivered after its provider refresh succeeds rather than claiming recovery from a failed request.
