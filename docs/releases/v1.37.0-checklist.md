# v1.37.0 release record

- Version 1.37.0, macOS build 73. Minor bump, and the reason is the same one v1.36.0 used: an account row changed what it renders. Three changes ship together — the watched row is no longer discarded when the same account also has a cloud row, the menu draws its own tooltips instead of relying on `.help()` inside NSMenu, and "how long ago" changes gear past an hour and past a day.
- Commits: `0aafe14` (tooltip layer: anchors report id + frame, the root layer draws the bubble), `6ce0f2d` (the age text), `c515514` (watched rows merge by freshness instead of being filtered out), `d2b2392` (release notes, version bump, homepage strings), plus the site-sync commit.
- **Two of the three changes were already in the working tree, uncommitted, when the release started** — the tooltip layer (`MenuView.swift` + `MenuTooltip.swift` + `MenuTooltipLayerTests.swift`) and the age text (`AppLanguage.swift` + `UpdatedAgoTextTests.swift`). The binary installed for verification at 20:57 was therefore built from a dirty tree and contained all three. That was fine here only because all three shipped; had the fix gone out alone, the artifact a user downloads would not have matched the commit range. **Check `git status` before `make install`, not just before `make pkg`.**
- The three changes are independent and each commit builds on its own: the tooltip commit uses the pre-existing `updatedAgoText`, and neither touches the merge layer.
- Validation: full Swift suite **658 tests, 4 skipped, 0 failures** (v1.36.0 was 645; the 13 new ones are 6 merge, 6 age-text, 1 tooltip). `swift build -c release` clean. Cloudflare `npm run check` clean; `npm test` **124 tests, 123 pass / 1 fail** — the pre-existing `tests/team.test.js:107` "dashboard session", identical to the last three releases and untouched here.
- `MobileDashboardSecurityTests.testLoopbackWakeVideoSupportsSafariByteRangesAndSecurityHeaders` — the load-sensitive 5-second-timeout test flagged in v1.36.0 — **passed** here. The machine was idle when the suite ran. Still worth fixing; still not fixed.
- **A first verification pass said the deploy had failed, and it had not.** After a successful `wrangler pages deploy`, `curl https://ai-quota-bar.pages.dev/` still served the v1.36.0 homepage. The build output in `dist-pages/` had the right strings, and re-fetching with a `?t=<timestamp>` cache-buster returned v1.37.0 immediately. Edge cache, not a bad deploy. **Verify a Pages deploy with a cache-buster, or the first check will lie.**
- **Hand-editing `content/releases.json` broke the file, and then broke `sync:releases` with it.** A text splice of the v1.37.0 entry produced invalid JSON, and because `sync-releases.mjs` parses the existing feed first, the next sync died with a parse error instead of regenerating it. Recovered with `git checkout -- cloudflare/content/releases.json`. The correct way to add `name_en` / `body_en` is to parse, replace the entry object, and write with the same `JSON.stringify(releases, null, 2) + '\n'` the script itself uses — that also keeps the key order (`tag_name, name, published_at, html_url, body, name_en, body_en`) identical to v1.36.0. After that the feed diff is exactly +9 lines, no existing entry changed.
- PKG SHA-256: `af6bbf3952486c4a2cb6ab988caa3ee7da495dee29e50f9121cf00539c184b04`. DMG SHA-256: `1716d993335f1d46370da5793ce98cf3e1762191590ce0851e828c054947097e`. `hdiutil verify` VALID on the DMG. `codesign --verify --deep --strict` passed on the app in `dist/` and again on the app re-extracted from the pkg payload (60 files, `CFBundleShortVersionString 1.37.0` / `CFBundleVersion 73`). `SHA256SUMS.txt` carries both, the published copy is byte-identical to the local one, and the assets **downloaded back from the release hash to exactly the published values**.
- The app inside the package was verified independently, not inferred from the build directory: `pkgutil --expand` on the pkg, then the component's `Payload` through `gzip -dc | cpio -i`, then a strict deep codesign check. `Distribution` carries `CFBundleShortVersionString="1.37.0" CFBundleVersion="73"` and the component `PackageInfo` carries both installer scripts (`preinstall`, `postinstall`, 600s each) — the earlier read of the package suggested they were missing, which was a grep that stopped at the opening `<scripts>` tag.
- The package is still **unsigned and not notarized**, unchanged from v1.35.0 and v1.36.0 — `pkgutil --check-signature` → "no signature". The release notes do not repeat that caveat; the install FAQ on the homepage states it instead.
- Tag: `v1.37.0` is **lightweight**, matching v1.33.0–v1.36.0 (`git cat-file -t` → `commit`).
- GitHub release: https://github.com/techfanseric/ai-quota-bar/releases/tag/v1.37.0 — published (not draft, not prerelease) with `AIQuotaBar.pkg`, `AIQuotaBar.dmg` and `SHA256SUMS.txt`, zh title/body per convention. Created **without** assets first and uploaded one at a time, capturing each command's exit status before any pipe — v1.36.0 lost a pkg that way to a pipeline reporting `tail`'s status. All three asset sizes on the release match the local files exactly, and `releases/latest` resolves to v1.37.0. No network retries were needed anywhere in this release.
- Website: `npm run sync:releases` synced 57 published releases; `name_en` / `body_en` for v1.37.0 added by hand as with every prior release. Homepage version strings updated in both languages (4 occurrences each, no `1.36.0` left). Deployed on the first attempt; `/`, `/en/`, `/changelog`, `/en/changelog` all 200, both changelogs render v1.37.0 with the correct language title and **no cross-language leakage**. `/v1/app-update` reports 1.37.0 pointing at the pkg.
- The Cloudflare token was read from `~/cf-fb-setup/secrets/cloudflare-api-tokens.md` **by account name** (the `node.cyberic@gmail.com` row), with the surrounding backticks stripped — 53 characters, not the 55 that the raw cell produces. The token was never printed, and the exported credentials were written to a `chmod 600` temp file that is removed after the deploy.
- Known boundaries, carried into the release notes: the watch merge needs a sample time on both sides and keeps the existing row when either is missing; the tooltip's 350ms delay does not follow the system accessibility setting, and its height is estimated from the line count purely to decide whether to flip above the row.
- The tooltip bubble now draws on top of the row it belongs to, which means a bubble for a row near the bottom edge can visually overlap the rows below it. The flip-above rule covers the panel window, not neighbouring rows. Worth a look on a tall menu with many accounts — the full suite renders the menu at several sizes and none of them caught it.
