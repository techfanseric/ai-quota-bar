# 关注账号（按邮箱公开查询）

## 这是什么

让一台 Mac 把自己的 Codex 额度**显示在另一台 Mac 的菜单栏里**，而不必在那台 Mac 上登录这个账号。

典型场景：小王有一台常驻跑 Codex 的机器，那台机器登录了某个账号；他自己另一台 Mac 想盯着这个账号的额度用，但不想、也不需要在那台 Mac 上登录它。

关注方要填的**只有一个邮箱**。不需要团队、邀请码、地址、端口、访问密钥，
也不需要在关注方登录 Codex。

## 传输：独立的公开查询通道

额度本来就产生在云端（OpenAI 的服务器）。app 自带的公共服务端点（`ai-quota-bar.pages.dev`）
上有一组专用的 `/v1/watch/*` 端点，用来发布和查询「某个 Codex 账号的额度快照」。

**它与团队体系完全无关**，这是刻意的：团队云同步是按团队隔离 + 设备凭据的，
关注一个账号不应该要求建团队，更不能借关注之名读到团队数据或设备凭据。

```
登录了账号的那台 Mac                         关注方那台 Mac
┌────────────────────────────┐             ┌──────────────────────────────┐
│ 本机 Codex 凭据 → 抓额度    │             │ 「我关注的账号」填一个邮箱    │
│            ↓               │             │            ↓                 │
│ 只投影勾选的账号             │  POST       │ GET /v1/watch/quota?email=…  │
│  百分比 / 重置时刻 / 套餐名  │ ──────────► │  邮箱本身就是查找键           │
│            ↓               │  app 内置 key│            ↓                 │
│ /v1/watch/publish          │             │ 与本机账号合并后按账号分组显示  │
│  整体替换：空数组=全部取消   │             └──────────────────────────────┘
└────────────────────────────┘
```

服务端存的是 `sha256(归一后的邮箱)`，表里没有明文邮箱。

## 为什么不是另外两条路

| 方案 | 为什么不选 |
| --- | --- |
| 把 `auth.json` 拷到本机 | 两台机器共用同一个 `refresh_token`，轮换时会互相把对方挤下线（`refresh_token_reused`）。 |
| 局域网点对点 | 要用户手填地址、端口和访问密钥，只在同一 Wi-Fi 下能用。v1.32.x 试过，v1.33.0 删掉。 |
| v1.33.0 的团队云同步 | 传输对了，但仍要求两台 Mac 先用邀请码加入同一个团队。用户要的是「只要知道账号」。 |
| 关注方自己登录这个 Codex 账号 | 需求本身就是要「不登录也能看」，而且多一份登录就多一份 `refresh_token` 轮换风险。 |

**Codex 登录凭据永远不离开登录它的那台机器**。线上传输的只有额度百分比、重置时刻、套餐名——没有任何能拿去调用 OpenAI 的东西。

## 设置在哪

**设置 → 服务商 → Codex → 关注账号**，一个区块里两半：

- **允许其他 Mac 关注我的账号**（分享侧）：全局开关 + 逐账号勾选。
- **我关注的账号**（关注侧）：一个邮箱输入框 + 一个添加按钮。

两半互不依赖，也都不需要团队。

## 使用步骤

1. **分享方那台 Mac**：打开「允许其他 Mac 关注我的账号」，勾选要分享的账号。
2. **关注方那台 Mac**：在「我关注的账号」里填入那个邮箱，点「添加」。
3. 之后跟着正常用量刷新更新，菜单里出现该账号的分组行，状态行显示「云端 · N 条 · 更新于 …」。

完了。**不需要建团队、不需要邀请码、不需要密钥、不需要两台机器在同一个网络。**

## 状态为什么分三种

三种「看不到数据」对应三种完全不同的用户动作，混成一句「无数据」会让人以为该重装点什么：

| 状态 | 含义 | 用户该做什么 |
| --- | --- | --- |
| `loading` | 正在获取 | 不用管 |
| `notShared` | 没有任何人在分享这个邮箱 | 让对方勾选这个邮箱 |
| `stale` | 对方分享了，但超过 3 小时没上报 | 确认那台 Mac 上的 app 还在运行 |
| `unreachable` | 网络失败 | 检查网络 |
| `available` | 有数据 | 不用管 |

## 安全边界

这个功能的边界比团队同步宽得多，值得把话说清楚。

**读路径对「知道这个邮箱的人」是开放的。** 这是这个设计的直接后果，不是疏漏：
不要求团队、不要求密钥，就意味着服务端没有可以核对的秘密。真正的授权是 owner
在设置里**逐个勾选**那个邮箱——勾了就是「知道这个地址的 Mac 可以看我的额度」，
取消勾选即刻失效。任何人都能算出一个地址的查找键，所以**哈希只保证服务端不存明文邮箱，
不构成访问控制**。

在这个前提下，仍然守住的：

1. **默认拒绝。** 打开分享开关后，只有**逐个勾选**的 Codex 账号会被发布；没勾的一个都不发。
   账号名为空的未归属额度同样不发（它没法被按邮箱关注）。
2. **只发百分比。** 对外只有额度百分比、重置时刻和套餐名。没有 token、没有 API key、
   没有绝对用量（绝对量会暴露这个人真实烧了多少）。`CodexAuthAccountStore` 的内容
   在这条链路上根本不可达。
3. **可以随时收紧，且立即生效。** 发布是**整体替换**语义，所以取消勾选会立刻从云端
   删除该行，不需要等下一轮刷新，也不需要单独的撤销接口。
4. **过期数据不冒充现值。** 超过 3 小时没更新的快照返回 `410`，UI 显示「数字可能是旧的」，
   而不是把旧数字当现值渲染。
5. **被读取是可查的。** 分享侧能看到每个账号被读取过几次、最后一次是什么时候
   （只含计数与时间，不含读取者身份）。owner 的手段是「取消勾选」，不是拉黑某个读取者。
6. **不转发别人的账号。** 分享名单取自**本机登录着的账号仓库**，不是从菜单那份已和
   团队云端合并的数据里取的——后者混着别人上报的账号，从那里取会让本机把同事的额度
   当自己的转发出去。
7. **不碰团队体系。** `/v1/watch/*` 是独立命名空间，不能读团队数据、设备凭据或后台；
   团队隔离（`docs/team-isolation.md`）的既有约束一条都没有放松。
8. **有速率限制。** 读取按来源 IP 限流（120 次/小时），发布按发布方限流（120 次/小时）。
9. **一个地址只能被一个发布方占用。** 第二个发布方会被 `409` 拒绝，否则原发布方
   后续的「取消分享」会删不掉这一行，账号会永久留在云端。

### 端点鉴权用的是什么

用 app 内置的 `SYNC_TOKEN`（每个安装都自带，零配置）。**它不是秘密**——就写在二进制里，
任何人 extract 一下就能拿到。它的作用是：挡住随手 `curl` 的探查、给读取一个归属桶、
让限流有依据。**不要把它当授权**：真正的授权是上面第 1 条的勾选。

## 与前两版的差别

**v1.32.1（build 62）**：局域网点对点。owner 端自己起一个明文 HTTP 服务，对端手填
IP、端口和一份自建的访问密钥。只能同一 Wi-Fi 用，还得先去「手机看板」翻密钥。
已删除：局域网端点 `/api/v1/watch/quota`、七个 `CodexWatch*` 类型、手机看板为此多起来的
「被关注也要监听」分支。

**v1.33.0（build 63）**：改走团队云同步通道。传输对了，但仍要求两台 Mac 先用邀请码
加入同一个团队，而用户要的是「只要知道账号」。该版本的上报过滤与启动读取改动
已在 v1.34.0 全部撤回：团队通道回到与本次功能无关的原有行为。

UserDefaults 里的 `codexWatch.isServing` / `codexWatch.grants.v1` 仍会被读取迁移，
用户之前勾过的账号不用重新勾。

## 已知边界

- **只覆盖 Codex。** 其它 provider（Kimi / GLM / MiniMax）各有各的凭据模型，
  混进来会让「允许分享」语义变模糊。
- **需要分享方那台 Mac 在运行。** 它关机或退出，云端里的快照会停在最后一次上报的时刻；
  超过 3 小时后状态变成「数字可能是旧的」，重新打开后自动恢复。
- **读路径对知道地址的人开放。** 这是「不要团队、不要密钥」的直接代价，
  缓解手段是逐个勾选 + 立即撤销 + 读取计数可见 + 限流，而不是共享秘密。
- **一个地址同时只能被一台 Mac 发布。** 同一个 Codex 账号在两台 Mac 上都登录并都勾选时，
  第二台会被 `409` 拒绝（否则第一台之后无法取消分享）。
