# 常驻负载与本机用量审查（2026-09-20）

## 现场证据

运行版本：1.22.0 (48)，macOS 27.0，10 核、16 GiB 内存。记录的是进程 CPU，100% 约等于占满一个核心。

- 退出前多次采样：约 64%–144% CPU；sample 物理占用 683.9 / 711.5 MiB，峰值 748.5 MiB。
- 同版本重启后：连续约 69%–105% CPU；sample 物理占用约 345.9 MiB，启动峰值 536.2 MiB。
- 重启后的主线程 227 个采样中，210 个经过菜单栏外观回调 → updateStatusItem → presentCompactButtonImages → renderedFrames。
- 其他应用同时有高负载，退出 AI Quota Bar 后整机仍忙，不能将整机负载变化全部归因于本软件。

## 原因与修复

1. AppKit 创建菜单栏副本快照时会临时改变子视图外观。此前每次外观回调无条件重建全部动画帧并重启播放。现在将回调合并到下一轮主队列，读取稳定外观；仅在实际可见输入、主题、缩放、尺寸或辅助功能状态改变时重新生成帧。倒计时/提示文字不使像素缓存失效。保留 30 fps 播放与 1x/Retina 图片。
2. 统计每次有文件变化就解析全部缓存、重新处理全部会话、全表排序并解码所有事件。现在持久化轻量文件头，仅处理变化会话的关联家族（父、子、续页和归档副本），按主键幂等写入。增加时间排序索引；逐行解码；界面只加载最近 35 天；无新事件时复用结果并保持图表缓存。
3. 本地上传状态容易把未绑定历史与真实待传混为一谈。设置页新增数据库/WAL/共享内存占用、原始日志占用、所有绑定的已确认/待上传/拒绝数、仅本地数、最早待传和最近回执时间。后续批次失败时刷新已完成批次的状态；核验按钮用现有设备身份只读比较云端记录数与 token 各分量。

监测、任务保护、额度刷新、网络检测及本地扫描频率保持原逻辑（扫描计时器仅允许 5 秒合并容差）。不自动上传原先未选择的历史。

## 数据量与上传范围

首次盘点：数据库约 229 MiB；事件表约 85.7 MiB，解析缓存约 111.5 MiB，其余主要是索引。

- 238,002 条历史未绑定上传目标，时间从 3 月到 9 月 17 日；不能视为云端备份。
- 当时 1,727 条绑定事件已经收到服务端确认，未发现绑定后的待传/拒绝积压；数量随运行增加。
- 最近约 35 天有 59,576 条，更早有 180,208 条（采样期间计数持续变化）。
- Codex 的 sessions 原始日志约 10 GiB，archived_sessions 约 448 MiB。这些由 Codex 管理，本软件只读，不在本次清理范围内。
- 新增索引会小幅增加磁盘占用。本次优化降低重复 CPU/内存开销，没有声称已经压缩数据库。

## 额度快照上传的独立故障

这条链路不同于 SQLite 中的本机 token 事件上报。继续盘点发现：

- 最近额度上传诊断反复为 HTTP 413；重试队列 54 个文件约 37 MiB（其中当前团队目录 50 个，另有旧版/其他归属文件）。
- 每份约 701–712 KB，包含全部利用率历史；当前团队接口 body 限制为 262,144 字节，且只存 models 额度快照，根本不读取 utilizationHistories。去掉该扩展后，现场单份请求约 2.3 KB。
- 修复新上传和旧队列重试：只发送当前团队协议实际支持的快照，本地利用率历史不变；新队列也只存精简快照。成功后继续排空队列，队列重放按时间排序，失败/成功均更新诊断，避免重试失败不可见。
- 原有额度重试队列每团队最多 50 份，超过会丢最旧快照。因此不能声称过往长期故障期间所有快照完整到达云端。它不影响独立的本机 token 事件持久化待传队列。
- 团队接口额度快照目前按服务器规则保留 90 天；本机 token 事件是另一种数据，不能混用这个保留承诺。

## 建议的历史保留规则（尚未启用）

| 时段 | 建议保留 | 目的 |
| --- | --- | --- |
| 最近 35 天 | 完整事件 | 覆盖左键本月、最近 24h 与 30 天统计 |
| 36 天至 1 年 | 按日、账号、模型、质量及价格生效区间汇总 | 保留准确 token/记录数、加权缓存命中率和可解释成本 |
| 1 年以上 | 按月汇总（建议保留至 3 年，再由用户决定） | 低频长期比较 |
| 未确认上传/被拒绝 | 保留原事件和诊断，独立于上述时间规则 | 防止漏传、便于修复 |

压缩还必须保留紧凑去重键，防止源日志重新扫描后重复入账；只清理可再生解析缓存，并保留分支依赖的恢复能力。跨时区日界、价格变更以及原始记录数不能用一条合成事件代替。已确认记录可在汇总校验后压缩；仅本地历史需要明确选择本地汇总或补传，不能擅自绑定到团队。

当前约 0.23 GiB 并非存储紧迫问题，而旧历史尚未全部上云，所以本次不自动删除/聚合历史。先将旧数据移出常驻内存，历史压缩可单独迁移和核对。

## 验证

- 最终定向 Swift 测试共 88 项：86 项通过，2 项专用 HTTP 集成测试因未启动对应服务器而跳过。覆盖增量关联会话、重启/归档、待传保留、缓存失效、月/24h 图表和中英文界面。
- 服务端用量上传测试 12 项、额度快照测试 9 项通过：幂等、内容冲突、身份归属、事务失败后重试等。新增客户端测试确认超限旧队列请求精简、失败保留原文件、成功移除和队列计数正确。
- 真实数据库副本：首次迁移/扫描约 14.87 秒，无变化复扫约 0.38 秒。239,825 条持久化事件；相较优化前副本，丢失旧 ID 为 0，旧事件正文/归属/投递状态变化为 0。
- 查询计划确认使用 usage_chronological 时间索引，不再临时排序。
- 发现 5 个历史会话因缺失祖先日志保持待解析。这是防止将复制的父会话用量重复计数的保守处理；因此“已产生事件的上传正常”不能等同于“全部原始日志均可完整统计”。
- 替换前同口径 60.97 秒采样：旧版平均进程 CPU 95.39%，中位区间 88.59%，最高 5 秒区间 157.90%。
- 正式 Release 构建和签名校验通过。新版首次启动被 macOS 钥匙串授权阻塞（sample 确认主线程等待 preloadCredentialVault，工作线程等待 SecItemCopyMatching）。该状态未进行监测，其低 CPU/内存不能用作优化结果。后续授权等待已解除，应用恢复扫描与实际上传；有效测量另行从正常工作状态开始。
- 为防止误报，初次阻塞期间的 /tmp/aiquota-optimized-observation.json 不作为性能证据。
